How trust works

Why a Fundi Finder rating means something

A star rating is only useful if you know it came from a real customer of a real job. Here is exactly how that is enforced, and where it can still fail.

{{ m.icon('lock', 24) }} 1. Reviews need a completion code

  1. You accept a quote. The booking page shows you a six-digit completion code. Nobody else sees it, including the fundi.
  2. On site, the fundi marks the work done in their account.
  3. You confirm by entering the code. If you do not have data on the day, you can read it to the fundi and they type it in. Either way the code is single use.
  4. Only now can you review, once, within 30 days. You can edit it for 14 days. The fundi can reply publicly. Anyone can report a review.

Five wrong guesses lock entry for an hour; ten disable the code until an admin re-issues it.

What it does not stop: a fundi who creates a fake customer and fake jobs. That is what the abuse checks below are for.

{{ m.icon('star', 24) }} 2. Ranking that resists gaming

Fundis are ranked by a score out of 100, not by average stars:

  • 55% review quality: a Bayesian average pulled toward the platform mean, so one 5-star review does not outrank sixty 4.8s. Recent reviews count more.
  • 15% completed, confirmed jobs.
  • 12% replying to requests within 24 hours.
  • 10% arriving on time.
  • 8% verification badges.

New fundis keep a clean score but hold every fourth result slot in search, clearly labelled, so they can earn their first jobs. The full formula, worked examples and failure modes are in docs/RANKING.md in the repository.

{{ m.icon('shield', 24) }} 3. Badges are computed from facts

  • {{ m.icon('check', 14) }}Phone verifiedA one-time SMS code was entered.
  • {{ m.icon('check', 14) }}ID checkedAn admin reviewed an uploaded identity document. The document is stored privately and never shown to anyone but admins.
  • {{ m.icon('check', 14) }}ReferencesTwo or more customers, from different phone numbers, confirmed they hired the fundi.
  • {{ m.icon('check', 14) }}Trade skillsThree or more portfolio photos.

{{ m.icon('alert', 24) }} 4. Abuse checks

Rate limits on sign-up, log-in, codes and requests. Heuristics flag clusters of reviewers whose accounts were created together, share a phone prefix or sign-up network, and reviewed only one fundi. Flags go to a human admin; nothing is removed automatically. Removed content can be appealed, and a different admin decides.

Honest scope. This is a portfolio build with synthetic data. There are no payments (M-Pesa is the natural next step), no real SMS, and it has not been field tested. Moderation at scale is not solved here.
